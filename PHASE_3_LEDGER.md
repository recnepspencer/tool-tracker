## Boundary brief

- Batch 2 remains closed and is the read-model authority. Batch 3 adds worker-originated commands without introducing component-owned state or a second fixture database.
- `createMockDatabase.update` is the atomic mutation boundary. Every custody command re-reads state, validates actor and lifecycle guards, and commits handoff/custody/condition/event changes together.
- Handoffs are retained after resolution so terminal replay is rejected and later reconciliation can inspect the decision. Only pending handoffs are projected into worker queues.
- This phase intentionally does not implement warehouse approval queues, admin reconciliation, peer-held request creation, real camera/upload storage, persistence across reload, or real concurrency.
- The source fingerprint covers the ten root config/package files, `public/tool-images/**`, and `src/**`; generated `dist/**`, ledgers, and browser evidence docs are excluded.
- Composition scope: the 400-line production-file law applies to the fingerprinted React implementation and its tests. The legacy `.dc.html` prototypes and `Nelson Electric tool custody system/support.js` are read-only reference artifacts retained for parity work; they are outside the application module graph, fingerprint scope, and production quality gate, so their historical line counts are explicitly exempt.
