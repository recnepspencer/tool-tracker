## Boundary brief

- The certified TanStack Query boundary remains the only adapter-backed UI seam. `src/app/providers.tsx` owns the application client, `src/test/render-app.tsx` owns per-test clients, `src/api/query-keys.ts` owns key vocabulary, and feature hooks are the only production callers of `NelsonApi`.
- `MockDatabase` remains the sole people, warehouse, custody, handoff, tool-unit, and audit authority. `ToolUnit.originWarehouseId` is immutable provenance; `assignedWarehouseId` is the current warehouse responsibility and changes only through an accepted warehouse return or the already-certified administrative removal flow that returns a held unit to its home warehouse.
- `WarehouseApi` is composed in both mock and HTTP adapters. Active administrators can review all warehouses; active warehouse managers can review only warehouses whose canonical manager reference is them. Workers and inactive members fail closed.
- Batch 5A owns queue classification, request/return decisions, and responsive inventory reads. Inventory edit/flag/decommission, reconciliation, full audit search, and settings remain in 5B/5C and are not enabled here.
- Composition scope: the 400-line production-file law applies to the fingerprinted React implementation and its tests. The legacy `.dc.html` prototypes and `Nelson Electric tool custody system/support.js` are read-only reference artifacts retained for parity work; they are outside the application module graph, fingerprint scope, and production quality gate, so their historical line counts are explicitly exempt, matching the closed Phase 3 policy.
