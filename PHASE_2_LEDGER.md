Scope: worker tools, pending handoffs, the supplied catalog, catalog filters and views, individual tool-unit detail, custody/timeline read models, worker activity filters, responsive worker navigation/account surfaces, and the mock/HTTP adapter evidence needed to keep those surfaces on one authority.

## Boundary brief

- The normalized mock database and `NelsonApi` contracts remain the only runtime authority. The prototype/reference `.dc.html` files are visual references, not data or transport sources.
- Batch 2 is read-only. Custody mutations, handoff decisions, damage/loss reporting, and admin reconciliation remain Batch 3–5 work; this phase seeds one pending handoff and one lost unit so the read surfaces are not vacuous.
- Catalog definitions group active units, but warehouse/status filters and detail actions operate on the selected unit records. Archived units are excluded from active catalog and coverage projections.
- Tool-bound activity and general audit events are distinct projections. A general audit event may appear in an admin summary without a fabricated tool reference; worker activity and tool timelines remain tool-bound.
- The checked-in browser diagnostic records the in-app browser parity run. Temporary viewport overrides are reset after the run and the clean fresh-tab console check is part of the evidence.
- `.phase-2-fingerprint.txt` is the frozen 200-file manifest for the ten root config/package files, `public/tool-images/**`, and `src/**`; its sorted SHA-256 lines use the same LF-delimited format as the Phase 1 fingerprint artifact. Generated `dist/**`, ledgers, and docs are excluded from the source fingerprint.

## Known open or intentionally deferred rows

- Custody mutations and handoff decisions are intentionally deferred to Batch 3; Batch 2 only proves the seeded pending read model and isolated async states.
- Image derivatives/thumbnails and performance optimization are deferred to the parity/static-delivery batch; canonical originals are shipped locally here.
- A Playwright package is not part of this static prototype's dependency graph. The repository carries a repeatable in-app-browser diagnostic and its latest run as the browser proof artifact; later parity work may promote it to a dedicated runner.
